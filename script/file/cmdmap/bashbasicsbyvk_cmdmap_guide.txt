COMMAND MAP — how every prompt in bashbasicsbyvk is wired
=========================================================

One rule: a typed word that is a command ALWAYS beats the natural action of
the prompt. To type such a word as plain text, put @ in front:

    s     → Settings                 @s   → the text  s
    @@s   → the text  @s             @john → stays  @john  (not a command word)

Typed a command that is blocked where you are?
    ❌ Invalid command: z — exiting     → the whole flow is cancelled, the menu redraws.
Typed  u  inside a prompt?              → go back one step (cancels only that prompt).
Typed  s / h / q  inside a prompt?      → that screen opens; you return to the prompt.

Prompts that print their own answers ([y/n], [Y/n, c = cancel], (a/b/c), [1-3]) are left alone.

ONE TRUTH PER KEY  (footer · cc · suggestion · what Enter does must never disagree)
    * The keys a prompt prints in its own text — "[c] continue · [r] reduce", "c) copy link   g) new link",
      "Enter) back" — are THAT prompt's answers and beat the map (same as a smart menu's footer).
    * u typed into a question (a name, a number, a time) is "go back ONE step": it cancels only that prompt
      (empty answer, _CM_BACKED=1, no abort flag; _mc_read returns 1).  The function that asked decides what
      one step back is: the question before (a flow with several questions runs them with _mc_steps) or the
      menu before.  Nothing after it (packing, uploading, deleting) runs.  A caller that reads an answer
      must stop when the read fails (rc 1 = back, rc 3 = cancel / EOF) or _CM_ABORT is 1 (a blocked command).
    * A menu's OWN key (switch: s, c, d ...) belongs to that menu's list prompt.  Inside a question it means
      the main command of the same name (s h q open that screen; c d r answer "Invalid command") or plain
      text when there is none.
    * "could become: ..." lists only keys Enter would accept in THAT prompt (_cm_usable — the same judge).
    * A footer key must be wired in the menu's .map AND handled by its loop.  tests/cmd_drift.sh guards this.
    * List screens that read keys themselves (Settings, Home: _st_run) take a typed word through _st_cm_gate: a command the map
      wires runs there, a blocked one answers "not available here".  tests/cc_truth guards this in a real pty.

Forgot a command?  Type  cc  (cheat codes) at any prompt: it lists exactly the commands THAT prompt
accepts (the effective table of its map, filtered by what the prompt kind can run). =lo filters, a
number picks; the command is then typed into the prompt for you and waits for Enter.
(engine/bashbasicsbyvk_cheatcode.sh — a new main command needs no extra work: it shows up in cc once
it is wired.)

FILES  (script/file/cmdmap/)
  bashbasicsbyvk_maincommands.sh        every main command, defined once:
                           cmd_def ID KIND HANDLER CLASS "description" ["example"]
  bashbasicsbyvk_<menu>menucommands.sh  commands that exist only in that menu (handler "-" = its own loop)
  bashbasicsbyvk_<menu>.map             the wiring of one menu / prompt
  bashbasicsbyvk_menus.list             which function owns which map (input of the generator)

.map SYNTAX
  @menu upgrade            @func upgrade_menu        @kind menu|prompt
  @back u                  @parent main

  p-   .mapto()  p-  from bashbasicsbyvk_maincommands.sh          # use the main command
  i-   .mapto()  k-  from bashbasicsbyvk_upgrademenucommands.sh   # this menu's own command, other key
  z    .mapto()  block()                           # main command blocked here
  u    .mapto()  back()                            # "go back"

  To reuse a key differently in one menu (say p- = paste in menu x), wire it in
  bashbasicsbyvk_x.map:   p-  .mapto()  p-  from bashbasicsbyvk_xmenucommands.sh   — it overrides main there only.

TOOLS
  o --map-show [menu]     the effective table of a menu (own + inherited, with source)
  o --map-lint            every main command a map has not wired explicitly
  o --map-gen             write missing lines into every map (never edits existing ones)
                          (= python3 cmdmap/bashbasicsbyvk_mapgen [--dry])

ADDING A MAIN COMMAND:  add one cmd_def line to bashbasicsbyvk_maincommands.sh, run  o --map-gen
(every map gets an explicit line: usable commands wired, others block()), then review.
Switch the layer off:  export VK_CMDMAP=0      Plain readline prompts:  export VK_CMD_EDITOR=0

ADDING A _xui_loop SCREEN (the screens that share bashbasicsbyvk_xui.sh: rbam, cloud surf, github, notifications ...):
  A screen with no map silently inherits the generic  xui  map, which BLOCKS c d r t f z ... and turns rf into the main redraw, so the screen's own
  keys stop working.  Every  _xui_screen X  that runs a loop therefore needs  cmdmap/xui_X/  (copy xui_ghr):
    bashbasicsbyvk_xui_X.map             @menu xui_X  @kind menu  @back u  @parent xui   + one  .mapto()  line per own key
    bashbasicsbyvk_xui_Xmenucommands.sh  cmd_def KEY exact|prefix - local "what it does" ["example"]
  + two  [no]  lines in the load mapper and  python3 script/file/loadmap/bashbasicsbyvk_loadmap_gen --write.
  Check:  bash tests/xui_wiring.sh   (a screen without a map, or an own key that does not resolve to the screen, fails).
