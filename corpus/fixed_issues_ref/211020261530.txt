1. ISSUE AS DEFINED BY USER
home/settings and other menus aren't showing suggestions (the dim "s  →  Settings (also: ...)" row that the main menu shows while typing). Everything should show suggestions.

1. HOW DID YOU DEBUG
_cm_hint (cmdmap.sh) builds the text; the main list paints it through _input_hint_sync (browse.sh), but only when _vp_hint_row=1, which _vp_geometry set only for the viewport input functions (_print_input_line, _sm_input_fn, _multi_print_input_line). Home and Settings are not viewport menus: they are _st_run / _st_draw (settings_ui.sh), which prints its own screen and never called _cm_hint. Confirmed in a pty (tests/nav_back App + vt.py): typing s on Home showed nothing, after the fix "s  →  Settings (also: sw, sv, sn, s-)". Checked Settings, Home, fx and main in tests/hints/hint_test.py. Other loop menus (fx, sw, api, bk, rules, upgrade, xui) already use _print_input_line and were fine; plain read -p prompts use _cm_text_read which already shows the hint.

1. CAUSE
Two separate screen engines; only one of them had a suggestion row.

1. FIX
settings_ui.sh: _st_hint_text (new) fills the blank row under the footer of _st_draw: _cm_ctx_find + _cm_hint for commands, plus "Enter → open/switch <row>" for a typed row number and a text for the = filter. Rule for the future: a new screen that draws its own "Select:" must call _st_hint_text / _cm_hint (tests/hints/hint_test.py covers main, Home, Settings, fx).
