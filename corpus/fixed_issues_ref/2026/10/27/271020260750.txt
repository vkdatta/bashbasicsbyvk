ISSUE IN BRIEF
`o` sourced about 130 library files (1.45 MB) through eight import files before the first paint, although the first screen calls only a fraction of them; the first paint waited for all of it (about 2 s on a phone). Wanted: one file that says per file whether it loads before the first paint, after it, or never until called, and a rule that every future file goes through it.

HOW DID YOU DEBUG
Read script/o, the eight import files and the owner's audit sheet. Traced a real start (bash xtrace through the pty harness of tests/paste_input/ptyapp.py) and listed the functions called before the first _vp_render_fresh: 111 functions in 26 of the 129 libraries. Wrote a static reader of the repo's bash style (top-level code vs function bodies, checked against the trace: 863 of 864 traced top-level variables found) and cross-referenced functions and top-level variables between files. Measured first paint inside the app (EPOCHREALTIME at the start of o and before the first read, 12 starts each): old 283 ms, new 167 ms, BVK_LOADMAP=all 270 ms (same as old). Compared the old full load with the new full load: same 1602 functions, bodies identical except the intended edits. Ran tests/run.sh all once: every test that passed before still passes; hints, settings_desc, choose_plain, delete_confirm, deps, wheel_target, choose and mouse were already red before the change (baseline run of the same tests on the untouched copy, same failure lines). The first full run showed nav_back, github_ui and loadtime_print red: the command map reads kind / handler of a menu's commands from `_CM_DEF`, which a lazily loaded *menucommands.sh had not filled yet; fixed (see FIX) and those three were rerun by name and pass. A pty smoke run of ~45 main-prompt commands (menus, staging keys, upload keys, gd, api, fx, health) printed no "command not found" / loadmap error. NOT verified: e2e_pending and e2e_services (need ../fileapi, skipped); real Termux timing; typing during the very first idle moment on a slow device.

CAUSE
Loading was eager and unconditional: o and eight _3bvk_import_*.sh files sourced every library in a fixed order, so the cost of a file was paid whether or not the first paint (or the whole session) used it. There was no per-file statement of when a file is needed.

FIX
New folder script/file/loadmap/: bashbasicsbyvk_loadmap.list (the mapper: [fg] before the paint, [bg] after it, [no] only when called; one line per file; WHY in the note column; @call lines run start-ups after the paint), bashbasicsbyvk_loadmap.sh (the loader: _lm_fg, _lm_idle, _lm_load, _lm_need, _lm_stub, _lm_all; background = idle moments inside the same shell, one file between two `read -t 0` key checks, because bash cannot hand functions from a child process to its parent), bashbasicsbyvk_loadmap_gen (python: --check / --write / --report; derives what each file needs loaded first from top-level calls, variables another file sets and redefined functions; refuses an [fg] file that needs a later or non-[fg] file, a [bg] file that needs a [no] file, a missing / stale mapper line, a top-level `declare` without -g), generated bashbasicsbyvk_loadmap_stubs.sh (needs table + one stub per function of every [bg] / [no] library). o: sources only the loader; python3 check before deps.sh is loaded; telemetry start and snapshot daemon moved after the paint (@call); Google Drive calls guarded by `_GD_ACTIVE`; `_lm_idle` before each prompt; --map-* tools call _lm_all. The eight app import files were deleted (rule 10). cmdmap.sh `_cm_parse_map` loads a menu's *commands.sh when the menu is wired. browse.sh / viewport.sh: no declare -F guard on a stubbed function. Top-level `declare -a/-A` became `-ga/-gA` in smartmenu, browse, health (a file now loads inside a function). cheatcode / colors / filter settings callbacks call `_lm_need bashbasicsbyvk_settings_ui.sh`. tests/loadmap.sh (new, fast), tests/adf_registry.sh and tests/smartload.sh now read the mapper. AGENTS.md: rule 13, rules 2, 3, 10 and the add-a-file checklist updated. Lesson: code in [fg] must never assume a [bg] / [no] variable exists; guard with ${VAR:-}, call a function of that file first, or `_lm_need` it. Follow-up candidates (files that are [fg] for only a few functions): fileapi_lib.sh and staging_pending.sh (the pending hint), viewport / displayer / cmdmap / browse / smartmenu (230 KB).
