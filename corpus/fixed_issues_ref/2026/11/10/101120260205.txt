1. ISSUE IN BRIEF
In Find and Find & replace, u did not go one screen back. At Pattern type, Match case or Where?, u left the whole option sequence and landed on the Find mode menu (or, from the CSV picker, on the main file list) instead of the question before it. The same happened at the text prompts and at the result / preview screens. Follow-up of BB-201020260021-1.

1. HOW DID YOU DEBUG
1. Read corpus index (Menus & Navigation) and note 201020260021: u had been fixed for the results screen only, as "back to the Find menu".
2. Read find.sh: _find_resolve_options asked Where? / Match case? / Pattern type? / Whole words? in a row and did `|| return` on the first rc 1 from _mc_select, so any u left the sequence. Callers mapped that to rc 3 = Find menu.
3. Text prompts were plain `read -p`: the command layer turns u there into a global abort (flag + muted output), which only a menu redraw clears.
4. _find_replace_csv did `open_csv_menu || return 0` and `[ -z "$csv_file" ] && return 0`: rc 0 = "done", so find_menu returned to the main file list. _find_replace never re-asked Single / Multi after u inside a flow.
(Verified by reading the code; tests run after delivery are listed in the status line.)

1. CAUSE
Each multi-question flow hand-rolled its own "u = leave the function" instead of one shared stepper, so u meant "back one level" in single menus and "leave the flow" in sequences.

1. FIX
- engine/bashbasicsbyvk_menuchrome.sh: new _mc_steps (STEPS-01): runs question functions in order; rc 1 = previous question, rc 1 on the first = caller goes back one level.
- functions/bashbasicsbyvk_find.sh: _find_resolve_options builds one step list (CSV picker, asked option questions, text to find, replacement, results / preview / confirm) and runs it with _mc_steps; settled options are not steps. Text prompts use _mc_text (prints u) Back, so u is the menu's own key). _find_replace loops back to Single / Multi when that question was asked; CSV picker z and the Apply-all question step back instead of returning 0.
Lesson: a flow with more than one question calls _mc_steps; never `|| return` after the first u.
