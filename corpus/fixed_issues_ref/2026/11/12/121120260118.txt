1. ISSUE IN BRIEF
In the upgrade menu (-u), typing a version number started the install straight away (after one Continue? question), and after a good install the screen only said to quit and start o again. Wanted: the number opens a version menu (Install / Info) like the file menu, Install needs no second question, and the program ends after a good install.

Read _upg_cmd_install, _upg_do_install and the choice loop in bashbasicsbyvk_upgrade.sh, and handle_file in bashbasicsbyvk_run.sh as the model for the menu.

1. CAUSE
Not a defect: the number was wired directly to the install, so the only way to look at a version first was i-N.

1. FIX
New bashbasicsbyvk_version.sh (handle_version: 0 Install, 1 Info; _hv_info) built from the shared menu pieces (_mc_header, _mc_options, _mc_footer @file_menu). bashbasicsbyvk_upgrade.sh: _upg_cmd_install remembers the pick (_UPG_PICK_N), loads the file with _lm_need and calls handle_version; _upg_do_install takes a third argument yes (already confirmed in the menu: no Continue?) and ends with exit 0 after a good install, because the running copy is the old version; the list is redrawn afterwards (_up_fresh=true). Loadmap line and regenerated stubs added for handle_version, _hv_info and the new upgrade helpers. Lesson: a number picked from a list opens that item's menu, as in the file list.
