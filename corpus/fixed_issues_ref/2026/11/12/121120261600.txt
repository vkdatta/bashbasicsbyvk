ISSUE IN BRIEF
Typed-line prompts were not one template: about 90 places called read, input() or getpass themselves, and 8 of them (switch.sh, localhost, gitpush, create, xtract, gen_sql, recover) bypassed the shared line editor, so later editor fixes (Shift/Ctrl keys, selection, highlight, tap) did not reach them.

HOW DID YOU DEBUG
Counted every read in script/ with a shell-aware scanner (the first regex scans missed reads inside case arms, one-line functions, builtin read and extension-less python tools, so earlier counts were too low). Read the read shim in smartmenu.sh: a `read -p` is already routed to _cm_text_read -> _cm_line_edit, but a read without -p, a `-s` read, and any process that does not load the shim (tools, python) is plain readline. Probed a stand-alone process in a pty: sourcing viewport, textedit, menuchrome, smartmenu and cmdmap is enough for _cm_line_edit to return typed text. Ran tests/prompt_template/read_lint.py (static lint plus a pty run of bashbasicsbyvk_ask: typed text, -i start text with Backspace, a Ctrl+Left word jump, a piped answer): all pass. Not run: the rest of the fast tier at the time of writing, and no real-app pty walk through every converted prompt; switch.sh Choice: now has a -p prompt, so the command layer and smart-menu detection apply there (verified by reading only).

CAUSE
Nothing forced a prompt to use the editor: the entry was the builtin name `read`, whose shim only catches calls with -p. Any prompt written another way, and every stand-alone tool, kept its own plain read, which is a copy of the editor that never gets later changes (drift).

FIX
Added _bvk_read VAR "Prompt" [-i] [-I] [-s] [-1] (smartmenu.sh, [fg]) as THE typed-line prompt; it returns what read returned, so callers are unchanged. Converted every in-app prompt (28 files, 76 mechanical edits by a tokenizer script, plus switch.sh x3). Added the stand-alone door: bashbasicsbyvk_ask (+ _3bvk_import_ask.sh, python door bashbasicsbyvk_ask.py) and converted localhost, gitpush, create, xtract, gen_sql, recover, recover_creds. _cm_line_edit: no command layer (a tool) means no hint row. Justified raw reads carry `# bvk-read-ok: <why>`. New tests/prompt_template/read_lint.py (registered as read_lint in tests.list, covers.map). AGENTS.md rule 16 (+ pointers in rules 6 and 14, check 8). Lesson: to change typing behaviour, change the editor behind _bvk_read once. Follow-up of BB-121120261500-1 (tap and cursor on every prompt); typed-line prompts in the app still have no tap (cmdmap turns mouse reports on only for the rename fill-in), which can now be added in _cm_line_edit for all prompts at once.
