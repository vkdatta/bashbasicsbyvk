1. ISSUE IN BRIEF
A user's own AI agent had no single place to learn the file picker (bashbasicsbyvk_filepicker), so it could not be told "use the bashbasicsbyvk filepicker instead of your native file picking tool or asking me to type a path", and the llms files did not say that the picker exists or where its guide is. Nothing made an agent that changes the picker update any documentation about it.

HOW DID YOU DEBUG
Read the shell door (bashbasicsbyvk_filepicker), the python door (bashbasicsbyvk_filepicker.py), the bridge (bashbasicsbyvk_qbridge.py) and the rules (bashbasicsbyvk_pickfilter.sh: _pf_parse, _pf_kind, _pf_kind_ok, _pf_allows). Ran the real parser over a matrix of rule strings against a sample folder (.csv, .CSV, .txt, .tar.gz, no extension, a folder) to record how rules combine: empty = files and folders, block beats allow, allow.ext alone = files only, allow(files,folders); allow.ext(csv) = .csv files and any folder, extensions are case-insensitive and may be compound, allow(csv) / allow() / pick(files) are refused with a message. Read the xlr8 guide, its test (xlr8_guide.sh), its loadmap line and its corpus note (BB-271120262042-1) to follow the same pattern.

CAUSE
The picker was documented only in comments of its own files. Those are not a place an agent is sent to, and no rule tied the picker to any guide.

FIX
New script/agents_guide/filepicker.txt: the complete reference for agents (what to say to the agent, keeping the guide current, what the picker is, requirements, the command language and how rules combine, the shell door with exit codes 0 / 2 / 3 / 64 and -s / -f, the python door with pick(commands, start, strict) and its exceptions, the keys inside the picker, where it can run (it needs the person's own terminal; a remote chat sandbox cannot show it), a procedure, ten parser-checked examples, errors, honest limits, a cheat sheet). New tests/pty/fast/engine/filepicker_guide.sh (registered in tests/pty/pty.list): every fenced example is accepted by the real _pf_parse; the behaviours the guide states (empty rules, allow(csv) and allow() refused, allow.ext alone refuses folders, the combination rule, block beats allow) are asserted; every verb and kind word of the parser, every exit code and option of the shell door and every public name of the python door must be in the guide; every repository path the guide names must exist; llms.txt and llms-full.txt must point at the guide; AGENTS.md must carry the rule. Mutation-checked (a dropped word, a broken example and a new exit code in the door each fail). AGENTS.md rule 19 (owner-permitted edit): changing anything in the file picker means updating the guide in the same change; a guide-only edit is a MINOR change. llms.txt: the free file manager mentions the picker; new File picker section (what it is, rules, doors, exit codes, agent instructions, guide URL) and a Docs link. llms-full.txt: new picker paragraph and agent paragraph in section 2, a new answer pattern, a link; section 9 (generated command reference) untouched. filepicker.txt is mapped in loadmap.list by its basename.
Static suite: no new findings; footer and intent time out at 25 s in this sandbox, also on the untouched upload.
NOT run: the picker in a real terminal and an agent using the guide end to end (the examples are checked by the rule parser only); importing bashbasicsbyvk_filepicker from user code outside the app (the guide gives a sys.path line based on shutil.which, not tested after a real pip install).
