1. ISSUE IN BRIEF
The v- buffer list (Shortpath buffers) printed a stray "-b" item in its footer, which is not a command, is not in cc and does nothing; the same stray item sat in the localhost port prompt. clr works in the three buffer screens (v- list, one buffer, one set) but neither their footer nor cc listed it, and cc's General tab never showed clr on any screen. The fx selection browser also took an "a" key (add all items here) that its footer and cc did not print. Follow-up of BB-251120262015-1 (footer unification) and BB-171120262130-1 (Settings clr / cc drift).

1. HOW DID YOU DEBUG
Read _mc_footer_std: it knows only -T, so any other argument is printed as a footer item; -b is a flag of _mc_select ("u) Back"), copied into the footer call. grep found exactly two such calls (staging_buffer.sh handle_staging_view, localhost.sh _lh_s_port). Read corpus note 251120262015: it removed the -b / -l flags from 37 footer calls and deleted the footer profiles, and put clr in _AD_GENERAL_KEYS ("never in a footer; cc still lists them"); these two call sites survived. Read advert.sh: cc lists only what a menu DECLARES, so a general key nobody declares is in no list, and _ad_footer_allow / _ad_footer_cells drop a general key from every footer. clr is wired only in switch, rules, Settings Group by and the buffers (cmd_def "Clear list"), so it is not a general command at all. Read menus.list: the three buffer loops (handle_staging_view, _sp_view_one_buffer, _sp_view_set) are not in it, so no map, no cc declarations, and t_footer / t_arms / t_advert (which only walk menus.list) never saw them; t_footer also only matches quoted "key:Label" items, so a bare -b can never match. Scanned every function that draws a footer and has a case loop: unregistered ones are the buffer views, _fx_sel_browse / _fx_sel_pick, _pick_groups, gcloud_navigator, local_navigator, _gp_body, _mc_review; only _fx_sel_browse (key a) disagreed with its footer. Ran: bash tests/run.sh once (footer and intent time out at 25 s in this sandbox, as the corpus already noted: run directly: footer 23 checks, intent 19,721 checks, 0 new), then structure, tidy, arms, advert directly after the fixes. pty: none run (static shows the footer and cc declarations; a screen check of v- is still worth one look on the device).

1. CAUSE
Two changes met. (1) The 25 Nov footer unification removed the -b flag from _mc_footer_std but two callers were not edited, so the flag became a footer item; no suite parses footer arguments other than "key:Label". (2) The same change declared clr a "general" key that is never printed in a footer, while only a few screens handle it and nothing declares it for the general tab, so clr vanished from the footers that had it (Settings Group by, the buffers) and from every cc. The static suites check only the menus listed in menus.list, so the unlisted buffer screens were never scored.

1. FIX
localhost.sh _lh_s_port: _mc_footer_std (no flag). staging_buffer.sh: handle_staging_view footer prints "clr:Clear all buffers"; _sp_view_one_buffer and _sp_view_set footers print "clr:Clear buffer / set / flat items" next to x and n. advert.sh: clr removed from _AD_GENERAL_KEYS (now " rf = "), so a screen that takes clr declares it and gets it in its cc (Menu Specific tab) and, budget permitting, its footer; Settings Group by (clr prio 90) is back in its footer. The three buffer loops are registered in menus.list (maps buffers, bufone, bufset written by mapgen, cmd_defs clr / x / n with the same descriptions the other menus use, files added to loadmap.list, template ID YWW6WZ in tidy.list). adf_selection.sh _fx_sel_browse footer prints "a:Add all". New static suite tests/static/t_blind.py (registered in suites.list): fails on a bare flag handed to _mc_footer_std, and on a footer-drawing loop that is not in menus.list and reads a key its footer does not print; checked to fail on the old tree (-b, clr, a). Lesson: when a flag or a profile is removed, grep every caller for it, and a screen that is not in menus.list is invisible to every map-driven suite; add a screen's loop to menus.list when it reads typed keys. Known finding left for the owner: structure labels:n (n is "New profile" in xui_gdp and "Rename set" in the buffers; same key, two meanings).
