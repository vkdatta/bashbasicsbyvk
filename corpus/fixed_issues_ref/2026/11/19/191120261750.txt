ISSUE IN BRIEF
Only four of the eight templates were drawn from; the main list, the tabbed menus and the list screens (auth, api, github, drive, cloudflare, notifications, rbam, cloud surf) still printed their own headers and footers, and a dozen prompts still typed "Select: " by hand. Every menu was to be wired through a template.

HOW DID YOU DEBUG
Read AGENTS.md, the definer, the processor and every _header / _footer function a viewport screen is given. Compared old and new output with a bash harness that extracts the old functions from a copy of the repo and runs both: 256 cases (main list flat / grouped / results, footer note, 7 tabbed screens with every tab, about 15 list screens with empty / filled / filtered states): byte-identical. The stand-alone ask tool's footer was compared old vs new through its import file: identical. Ran loadmap_gen --write, tidy_gen --check and bash tests/run.sh (11/11). NOT run: pty tests; clicks, resize and live redraw are verified only by the output comparison.

CAUSE
The layouts were declared but the screens kept their own echo / printf rows, and nothing flagged a screen that did.

FIX
New in the definer: {status_row}, {header_notes}, {filter_line}, {tab_bar}, {tab_description}, {count_line}, {tab_gap}, {footer_note}. New processor helpers: _tpl_footer ID items (a footer through the chrome) and _tpl_list_header TITLE [ROWS]; tabmenu got _tm_head (replaces _tm_header + the screen's own count / extra rows) and _mc_footer_std got -T ID. Templates rewritten to match what the screens print: JR9TZ5 (main list: _menu_header, _menu_header_flat / _imaginary, _menu_footer_lines, results), V3PX4Y (rbam, csurf, switch, fx, github tags, upgrade, rules), 7P68NA (auth x3, api, github repos, drive profiles, cloudflare, notifications, cs_pp, ct, ru, ux_pk). T5FL4F drew the same layout as 7P68NA and was merged into it (its screens now say 7P68NA; xui_rb / xui_cs / xui_ghr, which are tabbed, say V3PX4Y; results is JR9TZ5, rename 7UH852, infinity and the review menu YWW6WZ). _au_pick_header / _xui_pick_header and the run / version / ask footers use YWW6WZ. 14 typed "Select: " prompts now read ${_TPL_ACCEPTOR}. New static suite t_templates.py (no exceptions list): a viewport header / footer function must reach the processor, nothing outside the chrome calls _mc_footer, nothing types "Select: ". Lesson: a rule that shortens a file shifts the line numbers of baseline ids (rules.sh); keep the line count when editing a file that carries a baseline entry. NOT migrated: the Snapshots screens (snapshot_menu, _snap_menu_device_view), which are plain echo menus with their own "   > " prompt.
