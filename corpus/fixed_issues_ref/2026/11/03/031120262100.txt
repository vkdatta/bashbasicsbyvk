1. ISSUE IN BRIEF
The rf command (Refresh) on the main list and in the sw / fx screens left a loading bar on screen that kept animating over the new shell and could not be closed. The same hole existed for any other path that exec's a new program from the app.

1. HOW DID YOU DEBUG
Read corpus index (smartload / loading bar entries) and bashbasicsbyvk_smartload.sh. handle_refresh (script/cmd/bashbasicsbyvk_refresh.sh) ends in `exec bash -l ...`; the other exec sites (o q/cd, sw cd, viewport exit) call _lt_cleanup first, which calls _sl_shutdown. Listed every exec in script/: engine_heal's restart `exec "$_o"` also skipped it. Verified by reading only; tests not run (deliver first).

1. CAUSE
exec keeps the PID and skips the EXIT trap, so _sl_shutdown never ran. The animator's only exit test is kill -0 on the app PID, which still succeeds after exec, and it was armed and never sent D, so it drew its bar forever (one more per refresh).

1. FIX
refresh.sh handle_refresh and engine_heal.sh now call _lt_cleanup before exec (same as the other exec sites). Safety net in smartload.sh _sl_anim: the animator also ends when /proc/<app>/cmdline no longer equals the command line recorded at start (_SL_PCMD), i.e. the app exec'd something else, so a future exec site that forgets the cleanup cannot leave an immortal bar. Lesson: every new `exec` of a shell/app must call _lt_cleanup first.
