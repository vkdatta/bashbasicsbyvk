ISSUE IN BRIEF
There was no way to run Google Cloud Shell from inside the app: gcloud had to be installed by hand, accounts were switched by typing gcloud commands, and a hung Cloud Shell session could not be stopped from the app. Wanted: fx → cloudshell → launch.cloudshell with saved Google-account profiles (c create, x remove like open.github.others), gcloud installed by the app's own installer, every profile switch done with gcloud config set account, a themed launch, and a command that switches Cloud Shell off.

HOW DID YOU DEBUG
Read AGENTS.md, the command-map guide, the open.github.others screens (gho / ghu) and their xui_gho map, the xui loop, the deps engine (rclone recipe), the loadmap list and the smartload hold rules. Checked the current gcloud auth login reference online (ACCOUNT argument and --no-launch-browser still exist). Verified by reading and by bash -n only before delivery; the static suite result is in the delivery status line. The launch itself (gcloud, network, a real Cloud Shell) could not be run in the build sandbox, so the connect bar, the ssh flags and the kill command are verified by reading only.

CAUSE
Nothing in the app knew gcloud beyond a bare dependency line (D|gcloud, "install it from the website") used by transfers. The standalone shell function the owner used (gcloud-fast) lived outside the app, drew its own colours and had two weak spots: the process id it watched was the parent shell's ($$ inside a subshell), so an aborted ssh was never noticed, and the LocalCommand flag carried a space, which gcloud splits into separate ssh arguments.

FIX
New: script/file/functions/cloudshell/bashbasicsbyvk_cslib.sh (accounts file as data, gcloud locate / status / switch / login, connect bar, launch, kill), script/file/loops/iloop/fx/cloudshell_fx/open_cloudshell/bashbasicsbyvk_adf_cloudshell.sh (screen csh: number opens a profile, c create, x remove, k switch off, rf reload; registered as cloudshell/launch.cloudshell), cmdmap/xui_csh (map + commands, the same shape as xui_gdp), four loadmap lines plus the WITH entry of functions.sh, the Functions|adf:cloudshell description. Installer: deps.list gets a real gcloud recipe (@gcloud+curl+tar+python3+openssl: official tarball unpacked to ~/google-cloud-sdk, its install.sh without rc-file edits, a link in $PREFIX/bin on Termux or ~/bin elsewhere), D lines for openssl and ssh, F|cloudshell; deps.sh gets _dep_gcloud_target and _dep_recipe_gcloud, and the PATH step of the rclone recipe moved into _dep_bin_on_path so both recipes share one copy (same behaviour). The connect bar writes the app's own [███░░] shape, runs under _bb_progress_begin / _bb_progress_end (smartload stays away), never sets terminal colours (the app applies the person's colours), watches $BASHPID, and signals "connected" with LocalCommand=:>FILE (one word, no space). Lesson: _ghx_users_c / _ghx_users_x and _csh_create / _csh_remove are near-duplicates (same flow, different noun and validation); a shared "saved names" helper in bashbasicsbyvk_xui.sh is the follow-up, left out here so GitHub's screens stay untouched. Static-suite side fixes: tests/static/t_templates.py cached a "not reached" answer found inside a call cycle, so its result changed with Python's hash seed (the untouched upload fails with PYTHONHASHSEED=4); it now caches only a yes or a top-level no. Three unquoted tests in deps.sh (isna, late_pip, late_npm) were quoted so the shell suite's line-number ids no longer shift. tests/static/baseline/shell.txt still lists the old line numbers: the owner may drop those 3 entries. Follow-up (seen on a phone): leaving Cloud Shell with kl there (kill -9 -1) left the remote app's terminal modes on the local terminal, so typed keys were repainted in the wrong row until `reset` was run. The local side never resets after the session; _cs_launch now ends with _cs_term_reset (DECSTR, scroll region, alt screen, mouse / paste / sync-output modes, keypad, autowrap, cursor, colours, clear, size re-probe) however ssh ended, without ESC c so the app's colours stay. Verified by reading and the static suite only; the repaint itself needs the phone.
