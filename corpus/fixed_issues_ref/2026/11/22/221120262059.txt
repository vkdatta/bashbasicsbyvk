ISSUE IN BRIEF
The Home menu was one flat list of 15 rows (Local Surf, Cloud Surf, Shared, Notifications, Switch, Functions, Rules, Help, Authenticate, Links, RBAM, Backup, Saved Surf, Snapshots, Pending), hard to scan on a phone, and Cloud Surf and Shared opened the same menu. Wanted: group it the way Settings is grouped: Local Surf, File API Surf (Shared, Links, RBAM, Backup, Saved Surf, Snapshots, Pending), Loops (Switch, Functions, Rules), Notifications, Help, Authenticate; Cloud Surf and Shared become one row.

HOW DID YOU DEBUG
Read screens/bashbasicsbyvk_home.sh, the Settings engine (_st_run nesting, _st_crumb, description keys), the description table, the == deep search (it indexes Home rows) and every test that walks Home by row number. After the change: static suite, the Home cases of tests/pty/slow/input/nav_back/nav_test.py (10 of 10 pass), and a direct check that the == search lists "Home › File API Surf › Pending" and opens it (INNER pn). tests/pty/fast/menus/settings_deep.sh fails the same 13 live-typing cases on the untouched upload in this sandbox, so those were not counted against the change.

CAUSE
Home was one _st_run screen with 15 rows and no sub screens. Cloud Surf (_inner_run cs) and Shared (_inner_run cs-recv = csurf_menu 1, the same menu on its Received tab) were two rows for one place.

FIX
screens/bashbasicsbyvk_home.sh: Home now has 6 rows; File API Surf and Loops open sub screens with _st_run (new _home_fapi_build / _home_loops_build / _home_sub_act / _home_fapi_open / _home_loops_open), shown as "Home › File API Surf" through a local _st_crumb like Pending does; u goes back one screen, q closes to the main loop (_BVK_TO_MAIN handled in both acts). Cloud Surf and Shared are one row, Shared, opening cs (the Given and Received tabs are one key apart; it used to open on Received). settings_desc.sh: Home keys cut to the 6 rows, new File API Surf and Loops screens and rows with their texts. select/filter/bashbasicsbyvk_deepsearch.sh: the == search reads the rows of the two sub screens too and labels them with their parent; _home_act passes a sub screen's tag on to _home_sub_act so a search hit opens straight from the results. Tests: nav_test.py (row numbers, new File API Surf / Loops back and quit cases), mouse_test.py (Help is row 5), settings_deep.sh (label of the Pending hit). Loadmap stubs regenerated. Lesson: a menu that gains levels must be checked in the == search and in every test that types a row number.
